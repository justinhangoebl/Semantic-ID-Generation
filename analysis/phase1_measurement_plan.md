# Phase 1 Plan: Measurement and Baselines

## Purpose

Establish reliable metrics so semantic-ID uniqueness and quality are comparable across runs and changes.

## What to change in this codebase

- Add a single metrics module or utility that computes uniqueness, per-layer usage, and entropy from semantic IDs generated by the model.
- Integrate metric logging into the training loop so metrics are collected every epoch and saved with run outputs.
- Ensure metrics are computed in a consistent way for all datasets and configurations.

## Where it fits

- Training loop and evaluation flow in [train_rq_vae.py](train_rq_vae.py).
- Semantic ID generation flow in [modules/rq_vae.py](modules/rq_vae.py).
- Optional export/analysis flow in [generate_semids.py](generate_semids.py).

## Implementation details

### 1) Centralize metrics

Create a small metrics utility (new module) that exposes:

- compute_uniqueness(sem_ids, codebook_size) -> dict
- compute_layer_usage(sem_ids, codebook_size) -> dict

Example structure:

```python
def compute_uniqueness(sem_ids, codebook_size):
	unique_ratio = torch.unique(sem_ids, dim=0).shape[0] / sem_ids.shape[0]
	per_layer_usage = []
	per_layer_entropy = []
	for layer in range(sem_ids.shape[1]):
		ids = sem_ids[:, layer]
		counts = torch.bincount(ids, minlength=codebook_size).float()
		probs = counts / counts.sum().clamp_min(1.0)
		per_layer_usage.append((counts > 0).float().mean())
		per_layer_entropy.append(-(probs * (probs + 1e-9).log()).sum())
	return {
		"unique_ratio": unique_ratio,
		"per_layer_usage": per_layer_usage,
		"per_layer_entropy": per_layer_entropy,
	}
```

### 2) Hook metrics into training

In [train_rq_vae.py](train_rq_vae.py), after each epoch:

- Call model.get_semantic_ids on a fixed evaluation batch (or full dataset once per validation_step).
- Pass sem_ids to the metrics utility.
- Log to console and wandb.

Example integration:

```python
if epoch % validation_step == 0:
	model.eval()
	with torch.no_grad():
		sem_ids = model.get_semantic_ids(data[:eval_n].to(device)).sem_ids
	metrics = compute_uniqueness(sem_ids, config.model.codebook_clusters)
	logger.info(f"uniq={metrics['unique_ratio']:.4f}")
	if config.general.use_wandb:
		wandb.log({
			"unique_ratio": metrics["unique_ratio"],
			"layer_usage": [u.item() for u in metrics["per_layer_usage"]],
			"layer_entropy": [e.item() for e in metrics["per_layer_entropy"]],
		}, step=epoch)
	model.train()
```

### 3) Persist metrics with outputs

In [generate_semids.py](generate_semids.py), include the metrics dictionary in the saved artifact:

```python
metrics = compute_uniqueness(semids, config.model.codebook_clusters)
torch.save({
	"semantic_ids": semids,
	"metrics": metrics,
	"config": config,
}, args.output_path)
```

## Required adaptations

- Use a uniform API for metric computation, not ad-hoc per script.
- Standardize the use of seed and batch size across baselines and metrics runs.
- Add a small metrics summary to logging (console and wandb), aligned with existing logging in [train_rq_vae.py](train_rq_vae.py).

## What to append

- Add a metrics summary section to the saved output metadata (alongside semantic IDs).
- Add a baseline run checklist: dataset, seed, batch size, model config hash.

## Why this helps

- Uniqueness and coverage can fluctuate with batch size and seed. A consistent measurement layer prevents false improvements.
- Per-layer usage and entropy reveal whether deeper layers are contributing to uniqueness or collapsing.
- Baselines give a clear reference for deciding whether later changes are improvements or regressions.

## Deliverables

- Metrics utility function(s) used across training and inference.
- Logged metrics per epoch and a final summary per run.
- A baseline run table for quick comparisons.
- must be logged in weights and biasses as well
